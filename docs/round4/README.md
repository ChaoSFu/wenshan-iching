首个场景：「面试学校后，接下来能顺利入职吗？」，小畜 → 贲，九二、九五动。题意固定（跳过分流），三种情形只差在时间事实上；另加一道同卦、性质不同的问题。

| 用例 | 背景里的时间事实 |
|---|---|
| interview-fresh | 刚面试完，对方没有说什么时候给结果 |

| interview-overdue | 对方说上周五前给答复，现在已经过了约定时间，还没有收到消息 |
| same-hex-contrast（感情） | 和好朋友因为一次借钱的事闹僵了，要不要主动先开口？ |

## 人工检查（初评，待你确认）

按规格的三件事逐份看过：

1. **有没有直接回应问题**：改版后 8 份第一句都直接给方向（例如"先别把入职当成定局：向面试学校问清反馈安排，同时留意其他学校的岗位"）；改版前第一屏是题意复述与处境描述，判断散在三条"观察"里，标题是「准备蓄势」「求助合作」这类泛化词（Luna 生成的旧版报告尤其明显，见 `screens/before-report-375.jpg`）。
2. **用户能否照着做**：三种情形的下一步有实质区别——
   - 刚面完：在一周内跟进一次，问预计何时反馈、要不要补材料；
   - 有日期未过：在"下周五前"先不催，同时核实一个备选岗位，过期再跟进；
   - 已过期：现在就发一次跟进，问结果或新的答复时间。
   改版前"有日期未过"一例的行动是去看别的招聘公告，没有处理"等到约定时间"这件事。
3. **现实事实有没有被编造**：改版后没有出现用户没给的日期、星期、录用概率或招聘进展；消息模板里用户没提供的细节一律用【岗位】【姓名】留空。校验器会拒绝用户没给的日期与"录用可能性很大"这类表述（`unsupported_date`、`probability`），本次 8 份都一次通过，没有触发。

需要你判断的点：
- Luna 在三个面试用例里都加了"请一位熟悉学校招聘的老师或同行帮你核对"，来自「牵复」（相互牵引）的映射，具体但略显套路；Sol 更直接。
- 感情用例里 Luna 把「富以其邻」解释为"修复关系要顾及双方"，属于引申，是否算"引用能支撑解释"请你定。
- 两个模型都把"七天内"作为建议的时间窗口，这是建议而不是事实，没有被校验器拦下，符合规则。

## Luna 与 Sol

同一简版结构下，Luna 的通过率与 Sol 相同，耗时相近，费用约为 Sol 的 1/18；文字比 Sol 稍长、稍泛（更常给"借助他人"类行动）。按附录 F.7 的规则，是否把线上报告换成 Luna 要等人工评审的贴合度结论；在此之前线上默认仍是 Sol，本机测试用 Luna。
